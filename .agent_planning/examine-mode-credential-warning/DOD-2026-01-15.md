# Definition of Done: Examine Mode Credential Warning

**Feature**: examine-mode-credential-warning
**Date**: 2026-01-15

## Acceptance Criteria

### Startup Warning

- [ ] Running `chaperone examine` displays a security warning after "Press Ctrl+C to stop"
- [ ] Warning text includes "WARNING" or similar attention-grabbing prefix
- [ ] Warning explicitly mentions authentication credentials will be transmitted
- [ ] Warning is visually separated from other output

### Per-Request Warning

- [ ] Request with `Authorization` header produces WARN log
- [ ] Request with `X-API-Key` header produces WARN log
- [ ] Request with only non-auth headers (Content-Type, Accept) does NOT produce warning
- [ ] Warning includes target host for context
- [ ] Warning appears at WARN level

## Testing Instructions

1. Start examine mode: `go run ./cmd/chaperone examine`
2. Verify startup warning appears in console output
3. Configure test client: `export HTTPS_PROXY=http://127.0.0.1:4010`
4. Make request with auth header:
   ```bash
   curl -x http://127.0.0.1:4010 -H "Authorization: Bearer test" https://httpbin.org/get
   ```
5. Verify WARN log appears for auth header detection
6. Make request without auth header:
   ```bash
   curl -x http://127.0.0.1:4010 https://httpbin.org/get
   ```
7. Verify NO auth warning appears

## Verification Checklist

- [ ] Code compiles: `go build ./...`
- [ ] Existing tests pass: `go test ./...`
- [ ] Manual verification of startup warning
- [ ] Manual verification of per-request warning with auth header
- [ ] Manual verification that non-auth requests do not trigger warning
