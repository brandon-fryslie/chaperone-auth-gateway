# Sprint Plan: Chaperone Run Mode - Application Launcher with Socket-Based Proxy

**Generated**: 2026-01-11
**Sprint Goal**: Transform `chaperone run` from a deprecated proxy launcher into a full-featured application spawner that manages child process lifecycle, socket-based proxy, and environment injection.

---

## Sprint Goal

Enable `chaperone run <service-name>` to spawn and manage application processes with automatic proxy configuration via Unix sockets, eliminating the need for manual environment variable setup while maintaining strong separation between proxy and application concerns.

---

## Scope

### In Scope (This Sprint)

1. **Process Spawning & Lifecycle Management** - Launch child process with command/args, wait for exit, forward signals
2. **Socket-Based Proxy Configuration** - Generate per-service socket paths, inject proxy env vars
3. **Configuration System** - Add [services.run] section, implement user/project config merging

### Explicitly Out of Scope (Future Sprints)

- TCP mode support (Unix socket only for MVP)
- Multiple concurrent service launches
- Process restart/supervision features
- Advanced signal handling (SIGHUP reload, etc.)
- Log aggregation/forwarding
- Resource limits (cgroups, ulimits)
- Health checks/readiness probes

---

##

 Work Items

### Deliverable 1: Configuration Schema Extension

**Why This First**: All other work depends on config structure. Must be completed before process spawning or proxy setup.

**Changes Required:**

1. **Add RunConfig to ServiceConfig** (`internal/config/config.go`)
   - Add RunConfig struct with fields: Command, Args, EnvFile, SocketPath, Stdout, Stderr
   - Add `Run *RunConfig` field to ServiceConfig
   - All fields with appropriate TOML tags

2. **Implement Config Merging** (`internal/config/merge.go` - NEW)
   - Load user config from `~/.config/chaperone/chaperone.toml`
   - Load project config from `.chaperone.toml` (cwd)
   - Merge strategy: **service-level replacement** (project service replaces user service entirely)
   - Server/logging/audit config: project overrides user fields

3. **Variable Expansion** (`internal/config/expand.go` - NEW)
   - Expand `$HOME`, `${VAR}`, `$VAR` in RunConfig fields
   - Support escaped variables `\$VAR` (literal)
   - Handle undefined vars (error vs empty string - default to error)

**Acceptance Criteria:**
- [ ] RunConfig struct added with all fields and TOML tags
- [ ] LoadWithMerge() function loads both user and project configs
- [ ] Service from project config completely replaces user service with same name
- [ ] Server config fields from project override user (address, port, socket)
- [ ] expandVars() expands $HOME and ${VAR} syntax correctly
- [ ] Missing required env vars in expansion cause error
- [ ] Unit tests verify config merging precedence
- [ ] Unit tests verify variable expansion edge cases

**Technical Notes:**
- Use service NAME as key for replacement (not host pattern)
- Merge server config field-by-field (not service-level for server)
- Variable expansion must happen AFTER config merge

### Deliverable 2: Process Lifecycle Manager

**Why P0**: Core functionality - everything else orchestrates around this.

**New Module**: `internal/run/spawner.go`

**Components:**

1. **ProcessManager struct** - Manages child process lifecycle
2. **Key Functions**: NewProcessManager, Start, Wait, Signal, IsRunning
3. **File Descriptor Handling** (`internal/run/fd.go` - NEW)
   - FDConfig struct with Stdout and Stderr fields
   - Support "inherit", "file:/path", "discard" modes

4. **Signal Forwarding Strategy:**
   - Parent receives SIGTERM/SIGINT → forward to child
   - Wait for child to exit (with timeout: 10s)
   - If timeout expires, send SIGKILL
   - Then stop proxy

**Acceptance Criteria:**
- [ ] ProcessManager can spawn process with command + args
- [ ] ProcessManager correctly inherits/redirects stdout/stderr per config
- [ ] ProcessManager.Wait() returns child's exit code
- [ ] ProcessManager.Signal() forwards signals to child process
- [ ] SIGTERM to parent → SIGTERM to child → wait → proxy stops
- [ ] If child exits naturally, proxy exits with same exit code
- [ ] Unit tests verify signal forwarding logic
- [ ] Unit tests verify FD redirection (inherit, file, discard)
- [ ] Integration test: spawn `sleep 5`, verify it runs and exits

**Technical Notes:**
- Use `exec.CommandContext` with context cancellation for timeout
- Child process should be in same process group for signal isolation
- Socket cleanup must happen AFTER child exits

### Deliverable 3: Environment & Socket Management

**Why P1**: Enables child to discover and use proxy.

**New Module**: `internal/run/env.go`

**Components:**

1. **Environment Builder** - Build environment for child process
   - InheritParent() - Copy parent environment
   - LoadEnvFile() - Parse .env file
   - SetProxyVars() - Add proxy environment variables
   - Build() - Generate final environment slice

2. **Socket Path Generation** - Generate `/tmp/chaperone-<service>-<pid>.sock`

3. **Proxy Environment Variables**:
   - HTTP_PROXY=http+unix:///tmp/chaperone-<service>-<pid>.sock
   - HTTPS_PROXY=http+unix:///tmp/chaperone-<service>-<pid>.sock
   - CHAPERONE_SOCKET=/tmp/chaperone-<service>-<pid>.sock
   - CHAPERONE_SERVICE=<service-name>

4. **Env File Loading**:
   - Format: Shell .env style (`KEY=value`, `# comments`, `KEY="quoted value"`)
   - Error if file doesn't exist (fail fast)

**Acceptance Criteria:**
- [ ] EnvBuilder can inherit parent environment
- [ ] EnvBuilder can load .env file in shell format
- [ ] EnvBuilder handles quoted values in env file
- [ ] EnvBuilder.SetProxyVars() adds all 4 proxy env vars
- [ ] GenerateSocketPath() creates path with service name and PID
- [ ] Missing env_file causes error and prevents startup
- [ ] Variable expansion works in env_file values
- [ ] Unit tests verify env file parsing edge cases
- [ ] Unit tests verify proxy var generation format

**Technical Notes:**
- Socket path format `http+unix://` is supported by many HTTP clients
- PID used in socket path is PARENT PID (proxy process), not child
- Env file loaded BEFORE variable expansion
