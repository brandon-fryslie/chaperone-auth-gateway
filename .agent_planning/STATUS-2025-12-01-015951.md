## What Works Now

The Chaperone proxy can now:

1. **Accept CONNECT requests** from HTTPS clients
2. **Identify managed domains** using service registry
3. **Perform selective TLS MITM** for configured services
4. **Generate dynamic certificates** signed by local CA
5. **Decrypt and inspect HTTP traffic** for policy enforcement
6. **Enforce service policies**:
   - Block disallowed HTTP methods
   - Block disallowed paths
   - Block oversized request bodies
7. **Establish upstream TLS connections** to real API servers
8. **Proxy HTTP requests and responses** transparently
9. **Tunnel non-managed domains** without inspection
10. **Validate certificate trust** correctly

### Example Flow (Working End-to-End)

```
Client → CONNECT api.service.com:443 → Chaperone
         ↓
Chaperone performs TLS MITM (presents dynamic cert)
         ↓
Client → POST /v1/endpoint → Chaperone (decrypted)
         ↓
Chaperone checks policy (method, path, body size)
         ↓
Chaperone → TLS to api.service.com → forwards request
         ↓
Chaperone ← 200 OK with response ← api.service.com
         ↓
Client ← 200 OK (encrypted) ← Chaperone
```

## Phase 3 Preview: Secret Management

With Phase 2 complete, the proxy can now decrypt and inspect requests. The next phase adds **credential retrieval and injection**:

### Phase 3 Goals
1. Implement `SecretProvider` interface and registry
2. Build credential_ref parser (protocol:path format)
3. Create `env:` provider (environment variables)
4. Create `file:` provider (with strict 0600 permission checks)
5. Add secret caching with 5-minute TTL
6. Define error types (ErrSecretNotFound, ErrPermissionDenied, ErrTimeout)

### First Integration Target
After Phase 3, we can inject credentials into proxied requests. The first target will be bearer token authentication for OpenAI API.
