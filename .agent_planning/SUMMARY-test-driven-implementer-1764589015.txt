ARCHITECTURAL DECISIONS
=======================

1. Request Modification: Strategies modify requests in-place rather than cloning
   - More efficient (avoids unnecessary copying)
   - Tests validate no side effects

2. Registry Pattern: Separate registries for secrets and auth
   - Clean separation of concerns
   - Allows independent registration/mocking

3. Backward Compatibility: Nil registries skip authentication
   - Supports testing without auth
   - Gradual migration path

4. Hostname Preservation: forwardRequest() uses original hostname:port
   - Fixes routing to test servers with dynamic ports
   - Service.HostPattern used only for policy, not URL construction

5. Error Mapping:
   - 503 Service Unavailable: Secret fetch failure (transient)
   - 502 Bad Gateway: Strategy not found or apply failure (config error)
