# Plan: CLI Test Coverage

## Goal
Add test coverage for the CLI commands (`cmd/chaperone/cmd/`) which are currently at 0% coverage.

## Current State
- **Files**: `init.go`, `root.go`, `run.go`, `setup.go` (783 total lines)
- **Coverage**: 0%
- **Target**: Improve overall coverage from 60.7% toward 80%

## Testing Strategy

CLI commands interact heavily with the filesystem and OS, so we'll use Cobra's built-in testing patterns:
1. Test command execution with mock output buffers
2. Test flag parsing and validation
3. Test file I/O operations using temp directories
4. Test error cases (invalid config, missing files, etc.)

### Test Categories

#### 1. Root Command Tests (`root_test.go`)
- Version flag output
- Help text output
- Command structure validation

#### 2. Init Command Tests (`init_test.go`)
- Valid service templates (openai, anthropic)
- Invalid service name error
- File creation and content verification
- Overwrite existing file warning

#### 3. Run Command Tests (`run_test.go`)
- Config loading validation
- Flag parsing (`--config` required)
- Invalid config path error
- Config validation errors
- `setupLogging()` function with different levels
- `getCAPath()` function

#### 4. Setup Command Tests (`setup_test.go`) - Skip or Minimal
- The setup command is macOS-specific (networksetup)
- Testing requires elevated permissions or heavy mocking
- May provide minimal test coverage focusing on parseable logic

## Implementation Approach

1. Create `cmd/chaperone/cmd/cmd_test.go` or individual test files
2. Use `t.TempDir()` for file operations
3. Use `bytes.Buffer` to capture command output
4. Execute commands directly via `cmd.Execute()` or `cmd.ExecuteContext()`
5. Focus on testable units (functions like `setupLogging`, `getCAPath`, `runInit`)

## Files to Create
- `test/cli_test.go` (following existing pattern of tests in test/)
  OR
- `cmd/chaperone/cmd/cmd_test.go` (tests alongside code)

## Complexity
- **Low**: Root command, init command tests
- **Medium**: Run command tests (requires temp config files)
- **High/Skip**: Setup command (OS-specific, requires mocking)

## Expected Coverage Gain
- `init.go` (74 lines) → ~80% testable
- `root.go` (40 lines) → ~70% testable
- `run.go` (271 lines) → ~50% testable (setupLogging, getCAPath, flag parsing)
- `setup.go` (398 lines) → ~20% testable (OS-specific)

Overall estimate: CLI coverage from 0% to ~40-50%, which should bring total project coverage from 60.7% to ~70-75%.
