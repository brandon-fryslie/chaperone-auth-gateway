Successfully implemented Phase 3 (Secret Management) for the Chaperone Authentication Gateway.

## Components Implemented

### 1. Parser (internal/secrets/parser.go)
- ParseCredentialRef() function splits "protocol:path" format
- Handles edge cases: empty strings, missing colons, empty protocol/path
- Supports Windows paths with colons (e.g., "file:C:/path")
- Preserves colons in path portion (splits on first colon only)

### 2. Registry (internal/secrets/registry.go)
- Thread-safe provider registry with RWMutex
- Register() to add providers by protocol name
- Get() to retrieve providers
- Fetch() convenience method for complete flow: parse → get provider → fetch secret

### 3. Environment Variable Provider (internal/secrets/env.go)
- Fetches secrets from environment variables
- Validates variable names (alphanumeric + underscore only)
- Returns ErrSecretNotFound for missing or empty variables
- Respects context cancellation

### 4. File Provider (internal/secrets/file.go)
- Reads secrets from files with strict permission checks
- Enforces 0600 or stricter permissions (rejects 0644, 0666, 0777)
- Follows symbolic links (checks target permissions)
- 1MB file size limit
- Trims whitespace from content
- Returns ErrSecretNotFound for missing or empty files

### 5. Caching Layer (internal/secrets/cache.go)
- Wraps Registry with 5-minute TTL caching
- Thread-safe using sync.Map for lockless reads
- Singleflight pattern prevents duplicate concurrent fetches
- Caches both successes and errors (negative caching)
- Supports manual invalidation and clearing
- Tracks statistics: hits, misses, size
