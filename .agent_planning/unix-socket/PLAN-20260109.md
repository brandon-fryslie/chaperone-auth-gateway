# Sprint Plan: Unix Socket Mode
Generated: 2026-01-09

## Sprint Goal
Enable Chaperone to listen on a Unix socket instead of a TCP port, improving security by avoiding network exposure.

## User Decisions
- Socket path configurable via both CLI flag and config file (CLI overrides config)
- Mutually exclusive: either TCP port OR Unix socket, not both

## Scope
**In scope (this sprint):**
- P0: Unix socket listener support in proxy server
- P1: CLI flag `--socket` for inject/run commands
- P2: Config file support for socket path
- P3: Update `chaperone check` to detect socket mode

**Explicitly out of scope:**
- Peer credential verification (future enhancement)
- Socket file permissions configuration (use sensible defaults)
- Systemd socket activation

## Work Items

### P0: Unix Socket Listener
Modify `internal/proxy/server.go` to support Unix socket listening.

**Acceptance Criteria:**
- [ ] Server can listen on Unix socket path instead of TCP
- [ ] Socket file created with mode 0660 (owner/group read-write)
- [ ] Socket file cleaned up on shutdown
- [ ] Existing TCP mode still works unchanged

**Technical Notes:**
- Use `net.Listen("unix", socketPath)` instead of `net.Listen("tcp", addr)`
- Clean up stale socket file before listening (check if exists, remove)
- Register cleanup in shutdown manager

### P1: CLI Flag Support
Add `--socket` flag to inject and run commands.

**Acceptance Criteria:**
- [ ] `chaperone inject --socket /path/to/sock` listens on socket
- [ ] `chaperone run --socket /path/to/sock` listens on socket
- [ ] When `--socket` provided, TCP port is ignored
- [ ] Error if socket path is invalid or not writable

**Technical Notes:**
- Add flag in `cmd/chaperone/cmd/inject.go` and `run.go`
- Pass socket path to server via config or new parameter

### P2: Config File Support
Add socket configuration to config file.

**Acceptance Criteria:**
- [ ] `[server] socket = "/path/to/sock"` in config enables socket mode
- [ ] CLI `--socket` overrides config file setting
- [ ] If both `socket` and `port` specified in config, socket takes precedence
- [ ] Config validation warns if both specified

**Config example:**
```toml
[server]
# Use socket instead of TCP (mutually exclusive with address/port)
socket = "/tmp/chaperone.sock"

# OR use TCP (default)
# address = "127.0.0.1"
# port = 4010
```

### P3: Update chaperone check
Update security check to reflect socket mode.

**Acceptance Criteria:**
- [ ] When running with socket: show ✅ instead of ⚠️ for "Unix socket"
- [ ] Show socket path in output
- [ ] Keep existing TCP warning when using TCP mode

## Dependencies
- None

## Risks
- Socket file permissions on different platforms
- Cleanup of stale socket files
