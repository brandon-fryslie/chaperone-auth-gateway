### Technical Challenge: CONNECT Blocking

**Problem**: CONNECT requests establish a tunnel BEFORE HTTP layer exists. Standard approach is:
1. Accept CONNECT
2. Return 200 OK
3. Pass bytes through

**In strict mode, we need to**:
1. Receive CONNECT
2. Check if host is configured
3. If not → **REJECT** the CONNECT

**goproxy API**:
- `goproxy.OkConnect` - accept and tunnel
- `goproxy.RejectConnect` - reject connection
- `goproxy.MitmConnect` - accept and MITM

**Solution**: Return different ConnectAction based on strict mode:
```go
if service.ShouldMITM(registry, host) {
    // MITM
    return &goproxy.ConnectAction{Action: goproxy.ConnectMitm, ...}
}

if cfg.StrictMode {
    // REJECT in strict mode
    log.Warn(reqCtx, "strict mode: blocked non-configured domain", "host", host)
    return goproxy.RejectConnect, host
}

// Default: transparent tunnel
log.Debug(reqCtx, "using transparent tunnel for non-configured domain", "host", host)
return goproxy.OkConnect, host
```

**Complexity**: MEDIUM - goproxy library support exists, just need config plumbing
