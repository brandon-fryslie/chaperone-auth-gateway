# Sprint Plan: Audit Logging Enhancement for FedRAMP AU-3 Compliance

**Generated**: 2026-01-11T04:35:00Z
**Sprint Goal**: Achieve FedRAMP AU-3 minimum compliance by expanding audit entry fields to capture "who" (source) and "outcome" (success/failure) for all security-relevant events.

---

## Sprint Goal

Expand Chaperone's audit logging from a single event type (credential_injected) to comprehensive security event coverage with full AU-3 field compliance, enabling FedRAMP audit requirements and SIEM integration.

---

## Scope

### In Scope (This Sprint)

1. **AU-3 Core Field Expansion** - Add required fields: client_ip, outcome, status_code, error, detail
2. **Event Taxonomy Expansion** - Add policy_denied, request_dropped, auth_header_stripped, auth_failure events
3. **Integration Points** - Wire new events into policy enforcer and strip handler

### Explicitly Out of Scope (Future Sprints)

- OCSF schema transformation (keeping JSON Lines with compatible field names)
- Tamper-evidence and log integrity (AU-9)
- Log rotation configuration
- Remote syslog transport
- Administrative events (server_start, server_stop)
- Async/buffered logging for high-volume scenarios
- FedRAMP AU-2 event list documentation

## Work Items

### P0: Expand Entry Struct with AU-3 Required Fields

**Why P0**: Without these fields, audit logs fail AU-3 compliance. This is foundational for all other work.

**Changes Required**:
1. Add `ClientIP string` field - Extract from `r.RemoteAddr`
2. Add `Outcome string` field - Values: `success`, `failure`, `blocked`, `pass_through`
3. Add `StatusCode int` field - HTTP response status when applicable
4. Add `ErrorMessage string` field - Error details on failure
5. Add `Detail string` field - Event-specific context

**Acceptance Criteria**:
- [ ] `audit.Entry` struct includes all 5 new fields with JSON tags
- [ ] Existing `credential_injected` events populate ClientIP from request
- [ ] Existing `credential_injected` events set Outcome="success"
- [ ] All existing tests pass with no changes to assertions
- [ ] New unit tests verify JSON serialization includes new fields
- [ ] JSON output is backward-compatible (new fields use `omitempty` where appropriate)

**Technical Notes**:
- Extract IP from `r.RemoteAddr` using `net.SplitHostPort()`
- Handle proxy headers (X-Forwarded-For) later - out of scope for now

### P1: Add Event Type Constants and Policy Events

**Why P1**: FedRAMP AU-2 requires logging of access control decisions. Policy denial events are security-critical.

**New Event Types**:
```go
const (
    EventCredentialInjected = "credential_injected"  // existing
    EventAuthFailure        = "auth_failure"         // NEW
    EventPolicyDenied       = "policy_denied"        // NEW
    EventRequestDropped     = "request_dropped"      // NEW
    EventAuthHeaderStripped = "auth_header_stripped" // NEW
    EventPlaceholderMismatch = "placeholder_mismatch" // NEW
)
```

**Integration Points**:
1. **policy_denied**: Add in `policyHandler()` when method/path/body rejected (handlers.go)
2. **request_dropped**: Add when drop pattern matches (handlers.go ~line 220)
3. **auth_failure**: Add when secret fetch fails or auth strategy fails (handlers.go ~line 353-377)
4. **placeholder_mismatch**: Add when placeholder doesn't match (handlers.go ~line 330-336)
5. **auth_header_stripped**: Add when strip patterns remove headers (handlers.go strip logic)

**Acceptance Criteria**:
- [ ] All 5 new event type constants defined in audit/logger.go
- [ ] `policy_denied` event logged with: method, path, policy_rule, outcome="blocked"
- [ ] `request_dropped` event logged with: path, drop_pattern, outcome="blocked"
- [ ] `auth_failure` event logged with: error message, outcome="failure"
- [ ] `placeholder_mismatch` event logged with: expected vs actual, outcome="pass_through"
- [ ] `auth_header_stripped` event logged with: headers removed, outcome="success"
- [ ] Integration tests verify events appear in audit log

**Technical Notes**:
- Policy handler already has `policyHandler()` function - add audit call before returning error responses
- Strip logic is in `authHandler()` - audit after successful strip, before injection
