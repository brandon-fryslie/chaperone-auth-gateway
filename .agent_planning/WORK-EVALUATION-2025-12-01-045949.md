### ⚠️ Observations (Not Issues)

1. **CloneRequest Not Used:** The CloneRequest helper exists but isn't used in the current implementation. This is CORRECT because:
   - MITM handler creates a fresh `upstreamReq` for each request
   - Strategies modify this new request (not the original)
   - No need to clone since we start with a new object
   - CloneRequest is available if future strategies need it

2. **HeaderStrategy Default:** The HeaderStrategy is hardcoded to "X-API-Key" when registered. The plan mentions this is for MVP and custom header names are deferred to Phase 7. This is consistent with the plan.

3. **Strategy Apply Signature:** Strategies modify requests in-place rather than returning new requests. This is CORRECT per the AuthStrategy interface design and works because strategies receive the new `upstreamReq`.
