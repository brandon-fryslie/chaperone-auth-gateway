## Risk Assessment

### Medium Risks

**1. CA Trust Workflow**

- **Impact**: Poor user experience if trust instructions unclear
- **Mitigation**:
  - Clear README with platform-specific trust instructions

  - Provide troubleshooting guide for certificate errors
  - Include trust commands in log output

**2. TLS Handshake Complexity**
- **Risk**: TLS handshake errors may be difficult to debug
- **Impact**: Users may see cryptic "certificate invalid" errors
- **Mitigation**:
  - Detailed error logging for all TLS failures
  - Clear error messages distinguishing CA trust issues from other problems
  - Integration test validates handshake works when CA trusted
  - Comprehensive test coverage for edge cases

**3. Integration Between Components**
- **Risk**: Service routing and MITM must integrate correctly
- **Impact**: Domains may not be MITM'd correctly, or transparent tunnel may break
- **Mitigation**:
  - Comprehensive integration test (CHAP-rtn)
  - Preserve Phase 1 behavior for non-configured domains (backward compatibility)
  - Test both MITM and transparent tunnel modes
  - Verify Phase 1 tests still pass

### Low Risks

**1. Certificate Caching Concurrency**
- **Risk**: Race conditions in certificate cache under high load
- **Impact**: Potential panics or incorrect certificates served
- **Mitigation**:
  - Use sync.Map (thread-safe by design)
  - Comprehensive race detector testing
  - Unit tests for concurrent access

**2. Performance Overhead**
- **Risk**: TLS termination adds latency vs transparent tunnel
- **Impact**: Slower request processing for MITM'd domains
- **Mitigation**:
  - Certificate caching minimizes overhead
  - Connection pooling to upstream
  - Acceptable tradeoff for credential injection capability
