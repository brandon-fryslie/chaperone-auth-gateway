# Plan: Chaperone Init Wizard with Smart Credential Detection

## Sprint Goal
Build a new `chaperone init` command that automatically detects how applications pass credentials and generates ready-to-use configuration.

## Scope

**In scope (this sprint):**
1. Core detection infrastructure (heuristics, evidence accumulation)
2. Interactive wizard CLI
3. TOML config generator

**Out of scope (future):**
- Query parameter detection
- Request body detection
- Policy auto-configuration (methods, paths)
- Keychain/file credential source suggestions

---

## Work Items

### P0: Detection Infrastructure

**New package:** `internal/init/`

| File | Purpose |
|------|---------|
| `types.go` | Finding, ServiceFindings, DetectorConfig, GeneratedService |
| `evidence.go` | Thread-safe evidence store (per-host findings) |
| `heuristics.go` | Detection algorithms with confidence scoring |
| `detector.go` | Request analyzer, wires heuristics to evidence |

**Detection Heuristics (headers only):**

| Priority | Heuristic | Confidence | Example |
|----------|-----------|------------|---------|
| 1 | Sentinel match | 100% | Value == user-provided sentinel |
| 2 | Known auth header | 90% | `Authorization`, `X-API-Key`, etc. |
| 3 | Auth keyword in name | 70% | Header contains "token", "key", "auth" |
| 4 | Credential value pattern | 60% | Starts with `sk-`, 40+ chars, base64-ish |

**Acceptance Criteria:**
- [ ] `Evidence` accumulates findings per host, thread-safe
- [ ] Findings deduplicated (same header updates confidence, doesn't duplicate)
- [ ] Sentinel value matching: exact match in any header value
- [ ] Known auth headers list reused from `handlers.go:136-149`
- [ ] Value patterns detected: `sk-*`, `pk-*`, long alphanumeric, base64
- [ ] Unit tests for each heuristic

### P1: Config Generator

**File:** `internal/init/generator.go`

**Strategy inference:**
- `Authorization` header → `bearer` strategy
- Other headers → `header:X-Header-Name` strategy

**Env var suggestion:**
- `api.openai.com` → `OPENAI_API_KEY`
- `api.anthropic.com` → `ANTHROPIC_API_KEY`

**Acceptance Criteria:**
- [ ] Generated TOML matches `config.Config` structure
- [ ] Auth strategy correctly inferred from header name
- [ ] Env var names suggested based on host pattern
- [ ] Output includes helpful comments
- [ ] Unit test: generated TOML parses successfully

### P2: Interactive Wizard

**Files:**
- `internal/init/wizard.go` - Flow controller
- `cmd/chaperone/cmd/init.go` - CLI entry point

**Wizard Steps:**

```
Step 1: Configure proxy
  - Address (default: 127.0.0.1)
  - Port (default: 4010)
  - Sentinel value (optional)

Step 2: Detection mode
  - Start proxy, show connection instructions
  - Display findings in real-time as detected
  - User presses Ctrl+C when done

Step 3: Review findings
  - List each host with detected auth pattern
  - User confirms inclusion (Y/n)
  - User provides env var name for credential

Step 4: Generate & save
  - Generate TOML config
  - Choose save location (default, cwd, custom, print-only)
  - Show next steps
```

**CLI Flags:**
- `--sentinel <value>` - Pre-set sentinel value
- `--yes` - Non-interactive mode, accept defaults
- `--dry-run` - Show config without saving

**Acceptance Criteria:**
- [ ] Interactive prompts work for address/port/sentinel
- [ ] Real-time feedback shows findings as detected
- [ ] Review step allows include/exclude of findings
- [ ] Saves to ~/.config/chaperone/chaperone.toml by default
- [ ] `--yes` flag works for scripted/CI usage
- [ ] `--dry-run` shows what would be generated

### P3: Proxy Integration

**Modify:** `internal/proxy/server.go`

Add `NewInitProxy()` factory (pattern from `NewExamineProxy()`):
- MITM all connections (like examine)
- Request handler calls `detector.AnalyzeRequest(r)`
- Passthrough behavior (no modification)

**Acceptance Criteria:**
- [ ] `NewInitProxy()` creates working detection proxy
- [ ] Requests forwarded unmodified to upstream
- [ ] Integration test: proxy detects auth headers
