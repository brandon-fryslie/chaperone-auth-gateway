```markdown
# Chaperone Roadmap

## Security Hardening

### High Priority
- [ ] **Placeholder token authentication** - Apps must present token for injection
- [ ] **Dedicated user mode** - Run as unprivileged `chaperone` user
- [ ] **Unix socket mode** - Replace TCP port with Unix socket
- [ ] **Ignore system proxy** - Upstream connections bypass HTTP_PROXY

### Medium Priority
- [ ] **Own CA bundle** - Ship trusted CAs, don't use system store
- [ ] **chaperone check command** - Security posture assessment tool
- [ ] **Audit logging** - Log all credential injections (redacted)

### Lower Priority
- [ ] **Memory protection** - mlock() to prevent swap
- [ ] **Secure zeroing** - Zero credentials in memory after use
- [ ] **Certificate pinning** - Pin certs for known services
- [ ] **Rate limiting** - Prevent credential abuse

## Other Features
(other roadmap items)
```

## Technical Notes

**Philosophy to convey:**
- Security is layered, not all-or-nothing
- Each layer adds protection independently
- We don't pester users, but make secure setup easy
- `chaperone check` tells you what you can improve without nagging

**Tone:**
- Informative, not alarmist
- Explain *why* each measure helps
- Acknowledge tradeoffs (complexity vs security)
